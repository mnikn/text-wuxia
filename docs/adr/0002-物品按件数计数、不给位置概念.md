# 物品按件数计数、不给位置概念

玩家的携带物记成一张「物品名 → 件数」的表，语义固定为"在玩家身上"；单件重量由引擎侧的物品登记表权威登记，不由内容侧临时声明。同一个物件一旦离开玩家（当掉的剑留在当铺柜台），它就不再是物品，而是一条剧情标记。理由是这一批只需要回答「身上有什么」与「多重」两件事：实例式是为「把东西放在某处再回来取」准备的，为开场里唯一一件遗物引入全量实例表不划算。将来真出现寄存需求时，升格是一次有据可依的重构——`物品名 → 件数` 的每一项都能无损展开成实例。

## Considered Options

- **计数式**（选中）：`物品名 → 件数`，只表示携带。「剑在当铺」用剧情标记记，不进物品表。
- **实例式**：每件物品一个实例 `{物品, 件数, 位置}`，位置 ∈ 行囊／某地点／某人物。能表达寄存与跨地点追踪，代价是每次读写都要先定位实例，重量求和、编译期校验与界面都要跟着走一遍。
- **混合式**：携带用计数式，另加一张只给唯一具名物件用的「物品位置」表。省不下实例式的复杂度，只省下它的通用性。

## Consequences

- 「剑已当」不是物品状态，是剧情标记。将来做赎回线时，当票（物品）与「已当」（标记）要一起推进，两者可能不同步——当票丢了而剑仍记在当铺柜上，这种情形得由赎回剧情自己声明规则，不能指望物品表兜住。
- 「身上有没有」一律由物品回答：能由物品反推的事实不另设标记（买过粮、抓过药），反推不出来的才设标记（已出门、已当）。这条分界是为了避免同一个事实记两份而漂移。
- 银钱不是物品（见 `CONTEXT.md` 的「银钱」），因此它不进这张表、也不计负重。

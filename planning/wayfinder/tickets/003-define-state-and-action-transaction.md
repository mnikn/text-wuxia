## Question

哪些状态必须持久化，玩家行动按什么原子顺序消耗资源、推进时间、改变世界并触发故事单元，SugarCube 历史状态与 TypeScript 核心之间谁拥有真相？

## Resolution

### 状态所有权

- SugarCube `State.variables.game` 保存唯一权威、可序列化的游戏快照。
- TypeScript 定义 schema、规则和事务执行器；它接收旧快照与行动意图，返回新快照，不保留第二份可变权威状态。
- Twee 与 Passage 只能提交行动或声明式效果，不能直接写持久字段。
- 正式游戏禁止使用 SugarCube 历史回退撤销行动；开发模式可提供隔离的调试回退。

### 状态分类

1. **持久状态**：玩家、世界、时钟、当前位置、关系、势力、武学、物品、故事进度、战斗、调度队列和 RNG。
2. **派生状态**：最大气血、有效武艺、时辰显示、可用行动等；随用随算，不进入存档。
3. **内容定义**：地点、人物模板、物品、武学和故事单元定义；从内容注册表读取，不复制到存档。
4. **界面状态**：面板、滚动位置和临时提示；不得影响领域规则，不进入核心存档。

所有人物、地点、物品、武学和故事引用使用稳定 ID。动态状态只保存 ID 与变化量；显示名称和静态定义来自内容注册表。所有持久字段与剧情标记必须注册命名空间、类型和默认值；未注册写入在开发期报错。

### 顶层结构与扩展策略

```text
GameState
├─ meta
├─ player
├─ world
├─ clock
├─ location
├─ relations
├─ factions
├─ martialArts
├─ inventory
├─ stories
├─ combat
├─ scheduler
└─ random
```

- 顶层使用领域化 `GameState`，不采用全局 ECS。
- 内容扩展依靠稳定 ID、注册表与领域模块。
- 战斗和世界模拟提供稳定小接口；未来出现多敌人、大量组合状态或数百个持续模拟 NPC 时，可以在模块实现内部换成局部 ECS，不改变顶层状态接口和故事 DSL。

### 提交单位

- 每个通过验证的玩家行动提交一次：移动、工作、训练、休息、物品使用、故事选择和战斗动作均属于行动。
- 打开人物、物品、日志、设置等界面不是行动，不提交游戏快照。
- 战斗中，玩家动作、敌人回应和回合末状态结算构成一个原子事务；存档不能停在半回合。

### 固定行动管线

```text
玩家意图
→ 前置条件验证
→ 创建事务草稿
→ 固定并记录 RNG
→ 支付即时成本
→ 执行动作效果
→ 集中推进时间
→ 按关键时间点处理世界变化
→ 结算期限、伤势、饥饿、疲劳等状态
→ 生成故事候选集合
→ 按优先级选择至多一个故事入口
→ 校验新状态
→ 原子提交
→ Passage 只读渲染
→ 执行存档、音效、统计等提交后副作用
```

本管线参考 [DoL 行动与 Passage 生命周期研究](../research/dol-action-and-passage-lifecycle.md) 中集中时间轴、跨边界结算和动作后事件选择的经验；不沿用 Passage 内直接写状态、渲染期随机或 Header/Footer 修补领域状态。

### 时间、调度与事件

- 长行动按下一个调度时间点分段跳跃，不逐分钟循环。
- 任务期限、伤势恢复、天气切换等使用持久化调度队列；时间跨过到期点时调用已注册处理器。
- 只有声明为可中断的事件能中断长行动；其他到期结果在行动结束后结算。
- 同时到期的强制事项按“致命状态、任务期限、剧情强制、环境变化、普通随机”排序；未展示事项保留在队列。
- 一次行动最多选择一个入口故事单元；该故事的后续节点通过显式链接推进。
- 具名人物的常规位置由静态日程计算；只持久化剧情造成的位置偏移、伤势、关系和不可用状态。

### RNG、错误与输出

- 权威状态保存确定性 RNG 的种子与游标；相同状态和行动产生相同结果。
- 非法行动不启动事务，不消耗时间、资源或 RNG；返回结构化失败原因并刷新可用行动。
- 事务内部异常回滚整个草稿，包括状态、时间、成本与 RNG。
- 事务统一返回 `committed`、新状态、结果描述、日志项、后续故事入口或失败信息；渲染和存档不进入规则实现。
- 渲染、音效、自动存档和分析统计只能在提交成功后执行。
- 开发与测试环境每次提交完整校验 `GameState`；生产环境校验受影响领域，存档读写时执行完整校验。
- 存档保留当前快照、玩家可见日志与最近有限条调试事务摘要，不采用完整事件溯源或全部历史快照。

### 不变量

- 任意时刻只有一份权威持久状态。
- 条件判断与渲染不得修改状态或消耗 RNG。
- 已拒绝或已回滚的行动与执行前状态完全等价。
- 时间只由行动事务统一推进一次。
- 每次提交最多产生一个当前故事入口，其余强制事项不会丢失。
- Passage、Header、Footer 与导航逻辑不得承担领域修复。
